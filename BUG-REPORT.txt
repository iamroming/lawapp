CRITICAL BUGS (Fix Immediately - App Broken or Data at Risk)
================================================================================

1. CSRF VALIDATION CRASH (middleware.ts)
   File: src/lib/csrf.ts:32-35
   Issue: crypto.timingSafeEqual() throws RangeError if buffers have different
   lengths. A malformed CSRF cookie with a short/empty signature will crash
   the middleware, returning 500 on every request.
   Fix: Check buffer lengths before calling timingSafeEqual.

2. CSRF SECRET USES PUBLIC KEY (csrf.ts)
   File: src/lib/csrf.ts:4
   Issue: When CSRF_SECRET env var is not set, the secret falls back to
   NEXT_PUBLIC_SUPABASE_ANON_KEY, which is PUBLIC. An attacker who knows
   the anon key can forge valid CSRF tokens, bypassing all CSRF protection.
   Fix: Throw error if CSRF_SECRET is not set. Never use public keys.

3. ACCOUNT DELETE IS FAKE (account/delete)
   File: src/app/api/account/delete/route.ts:37-39
   Issue: Calls updateUserById with ban_duration: "none" which does NOTHING.
   User can still log in after "deleting" their account.
   Fix: Use supabase.auth.admin.deleteUser(user.id) instead.

4. TEAM DELETE UNUSABLE BY OWNERS (team/[id])
   File: src/app/api/team/[id]/route.ts:36
   Issue: Condition uses || instead of &&. Owners MUST be both owner/partner
   AND super_admin to delete team members. Regular firm owners cannot manage
   their own teams.
   Fix: Change || to && or restructure the check.

5. DAILY DIGEST LEAKS ALL FIRMS' DATA (daily-digest)
   File: src/app/api/daily-digest/route.ts:47-62
   Issue: Hearing queries fetch ALL hearings without firm filtering. Every
   firm's digest contains every other firm's court dates.
   Fix: Add firm_id filtering to all hearing queries.

6. INVOICES REMINDERS CRON BROKEN (invoices/reminders)
   File: src/app/api/invoices/reminders/route.ts:71-76
   Issue: Cron creates service-role client but query filters by
   .eq("issued_by", null) where userId is null for cron calls. The cron
   never finds any invoices to remind about.
   Fix: Remove the issued_by filter for cron context.

7. FORMAT-NUMBER-TO-WORDS BREAKS ON DECIMALS (india/gst.ts)
   File: src/lib/india/gst.ts:56-73
   Issue: When called with decimal amounts (e.g., 1550.50), the function
   produces "undefined" in output text because float indices don't exist
   in the number-to-word arrays. Used in ALL invoice PDFs.
   Fix: Math.round(num) at the top of the function.

8. FINANCIAL YEAR Q4 DATE WRONG (india/financial-year.ts)
   File: src/lib/india/financial-year.ts:58
   Issue: Q4 start date uses fy.startDate.getFullYear() which gives the
   PREVIOUS year. For FY 2025-26, Q4 should be Jan 1, 2026 but code
   produces Jan 1, 2025.
   Fix: Add +1 to the year calculation for Q4.

HIGH BUGS (Security or Major Functionality Issues)
================================================================================

9. COURTS API ROUTES HAVE NO AUTH (15 routes)
   Files: src/app/api/courts/*/* - ALL 15 routes
   Issue: Zero authentication checks. Anyone can proxy requests to the
   external court service, abuse rate limits, or enumerate case data.
   Fix: Add auth checks to all court routes.

10. CLIENTS/FEEDBACK POST MISSING AUTH CHECK
    File: src/app/api/clients/feedback/route.ts:49-63
    Issue: Auth check happens after input validation but before DB insert.
    If user is null, it inserts user_id: null.
    Fix: Move auth check to the top of the handler.

11. TASKS PATCH ALLOWS ARBITRARY FIELD UPDATES
    File: src/app/api/tasks/route.ts:86-112
    Issue: const { id, ...updates } = body is passed directly to .update().
    Users can overwrite firm_id, user_id, created_at, etc.
    Fix: Whitelist allowed fields before passing to update.

12. EXPENSES PATCH ALLOWS ARBITRARY FIELD UPDATES
    File: src/app/api/expenses/route.ts:107-133
    Issue: Same as above - spreads all body fields into .update().
    Fix: Whitelist allowed fields.

13. CONSULTATIONS PATCH ALLOWS ARBITRARY FIELD UPDATES
    File: src/app/api/consultations/route.ts:68-95
    Issue: Same pattern - spreads all body fields into .update().
    Fix: Whitelist allowed fields.

14. COUPONS/apply RACE CONDITION (TOCTOU)
    File: src/app/api/coupons/apply/route.ts:38-40, 109-118
    Issue: Checks current_uses >= max_uses, then later increments.
    Two concurrent requests can both pass the check and both insert,
    exceeding max_uses. Financial impact with paid coupons.
    Fix: Use atomic .increment("current_uses") instead.

15. INVOICES RACE CONDITION ON NUMBER GENERATION
    File: src/app/api/invoices/route.ts:65-70
    Issue: Invoice number is based on count(). Two concurrent requests
    can get the same count, producing duplicate invoice numbers.
    Fix: Use a database sequence or RPC for generation.

16. CONFLICT CHECK SCOPED TO USER NOT FIRM
    File: src/app/api/clients/conflict-check/route.ts:21,43,63,84
    Issue: All four conflict queries filter by created_by = user.id
    instead of firm_id. Partners can't see conflicts created by associates.
    Fix: Change to firm_id filtering for firm-wide conflict checks.

17. NOTIFICATIONS SERVICE USES BROWSER CLIENT SERVER-SIDE
    File: src/lib/notifications/service.ts:1
    Issue: Imports createClient from supabase/client (browser client).
    This service is called from API routes (server-side). Can bypass RLS.
    Fix: Import from supabase/server instead.

18. I18N PROVIDER NEVER MOUNTED
    File: src/i18n/provider.tsx - exported but never imported anywhere
    Issue: LanguageSwitcher renders but selected locale is discarded.
    All translations are always English.
    Fix: Wrap layouts with I18nProvider, or remove dead code.

19. CLOUDINARY DELETE USES WRONG RESOURCE TYPE
    File: src/app/api/documents/delete-cloudinary/route.ts:38
    Issue: Hardcoded to image/destroy. PDFs and other non-image files
    will fail to delete from Cloudinary storage.
    Fix: Accept resource_type parameter or detect from file extension.

20. REDIRECT LOOP RISK FOR /ONBOARDING
    File: src/lib/supabase/middleware.ts:89-93
    Issue: If user has no profile and visits /onboarding, middleware
    checks: !profile && pathname !== "/onboarding". This works, but
    if the profile check fails for any other reason, infinite loop.
    Fix: Add /onboarding to publicRoutes array.
