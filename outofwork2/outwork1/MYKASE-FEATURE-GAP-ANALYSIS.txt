## PART 2: MISSING FEATURES — IMPLEMENTATION PLAN

### PRIORITY 1: CORE GAPS (Must-Have, 0-30 days)

#### 1.1 Expense Management
```
DB: expenses table
  - id, case_id, user_id, firm_id
  - amount, description, category (court_fees/travel/filing/notary/other)
  - is_billable (boolean)
  - receipt_url (Cloudinary upload)
  - date, created_at

Pages:
  - /expenses — list with search, filters (case, user, date range, billable)
  - /expenses/new — add expense form
  - /expenses/reports — spending by category/case/user

API:
  - /api/expenses — CRUD
  - /api/expenses/reports — aggregated stats

Integration:
  - Link expenses to invoices (billable expenses auto-added to invoice)
  - Expense reports in /reports
```
Effort: 3-4 days

#### 1.2 Task Management
```
DB: tasks table
  - id, case_id, assigned_to, created_by, firm_id
  - title, description, status (pending/in_progress/completed)
  - priority (low/medium/high/urgent)
  - due_date, completed_at

Pages:
  - Tasks widget on case detail page
  - /tasks — my tasks / all tasks view with filters
  - Task board (Kanban) view optional

API:
  - /api/tasks — CRUD with case linking

Integration:
  - Task assignment sends notification
  - Overdue tasks show on dashboard
  - Link to calendar
```
Effort: 2-3 days

#### 1.3 Timesheet Management (Full UI)
```
Existing: time_entries API exists

Add:
  - /timesheets — weekly/monthly timesheet view
  - Start/stop timer on case detail page
  - Manual time entry form
  - Billable hours report per lawyer/case/client
  - Export timesheet as CSV/PDF
  - Link time entries to invoices

Pages:
  - /timesheets — main timesheet page
  - Timer component on case detail page

API:
  - Enhance /api/time-entries with aggregation endpoints
  - /api/timesheets/report — billable hours by lawyer/case
```
Effort: 3-4 days

#### 1.4 Personalized Cause List
```
DB: user_court_preferences table
  - user_id, court_code, court_type (sc/hc/dc)
  - notify_on_cause_list (boolean)

Pages:
  - Add "My Courts" section to dashboard
  - Auto-fetch cause list for preferred courts
  - Show filtered cause list on dashboard

API:
  - /api/user-court-preferences — CRUD
  - Enhance dashboard to show personalized cause list

Integration:
  - Daily cron fetches cause list for all user-preferred courts
  - Send WhatsApp/email alert when cause list has user's cases
```
Effort: 2-3 days

#### 1.5 Case Status Alerts
```
DB: case_alerts table
  - id, case_id, user_id, alert_type
  - last_status, current_status
  - channel (email/whatsapp/sms/in_app)

Flow:
  1. User links case to eCourts CNR
  2. Cron job polls case status daily
  3. If status changes → send alert via all channels
  4. Store alert history

API:
  - /api/case-alerts — CRUD
  - /api/case-alerts/check — cron endpoint
  - Enhance eCourts sync to include status comparison

Integration:
  - Reuse existing WhatsApp/email infrastructure
  - Dashboard notification when status changes
```
Effort: 3-4 days
