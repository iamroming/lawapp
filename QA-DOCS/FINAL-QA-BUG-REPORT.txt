CRITICAL BUGS (Security / Data Loss / Crash)
======================================================================

#1 Employee Signup Completely Broken
  File: src/app/api/auth/signup/route.ts:79-81
  Bug: API always rejects non-owner signups with 400 error.
       Frontend offers "I'm a Team Member" mode but API blocks it.
  Impact: Employee onboarding is dead code. New team members cannot
          sign up even with valid invite codes.

#2 Zombie Users on Profile Failure
  File: src/app/api/auth/signup/route.ts:59-97
  Bug: createUser() succeeds at line 59, then profiles upsert at
       line 84 may fail. User gets 500 but auth account exists.
  Impact: Zombie auth users with no profile. Can never complete
          onboarding. Duplicate signup attempts create more zombies.

#3 Billing Pages Infinite Re-Render
  Files: billing/new/page.tsx:28, billing/outstanding/page.tsx:38
  Bug: createClient() called inside component body on every render.
       New object reference causes useEffect to re-run infinitely.
  Impact: CRASH. Both billing pages are completely unusable.

#4 New Case/Client Forms Missing firm_id
  Files: cases/new/page.tsx:183-205, clients/new/page.tsx:88-91
  Bug: inserts have no firm_id. Cases/clients created without firm
       association. Owners filter by firm_id so they're invisible.
  Impact: Data orphaned. Created records vanish from owner's view.

#5 Case Detail IDOR (Insecure Direct Object Reference)
  File: src/app/(dashboard)/cases/[id]/page.tsx:82-86
  Bug: No firm_id filter on case fetch. Any authenticated user can
       view any case by navigating to /cases/{arbitrary-id}.
  Impact: Cross-firm data leak. Firm A can see Firm B's cases.

#6 AI Research Imports Server-Side Code
  File: src/app/(dashboard)/ai/research/page.tsx:10
  Bug: searchLegalResearch from @/lib/ai/service accesses
       process.env.AI_API_KEY — a server-only secret.
  Impact: Research feature always falls back to hardcoded results.
          AI_API_KEY is always undefined in the browser.

#7 AI Research No Usage Tracking
  File: src/app/(dashboard)/ai/research/page.tsx:40-54
  Bug: Unlike all other AI pages, research has no useAiUsage().
       No isAtLimit check. No rate limiting.
  Impact: Free plan users get unlimited research queries,
          bypassing all plan restrictions.

#8 Calendar Data localStorage Only
  File: src/app/(dashboard)/calendar/page.tsx:187-195
  Bug: Court rules and events stored in localStorage, not DB.
       Lost on browser clear, device switch, or different browser.
  Impact: Data loss for SaaS product. Not shared with team.

#9 Subscription Query Missing Status Filter
  File: src/app/(dashboard)/subscription/page.tsx:82-89
  Bug: Fetches most recent subscription regardless of status.
       Could return cancelled/expired instead of active.
  Impact: User sees wrong plan. Upgrade/downgrade buttons incorrect.

#10 Documents Crash for Employees
   File: src/app/api/documents/route.ts:34
   Bug: .or() filter with empty caseIds array produces
        case_id.in.() — invalid PostgREST filter = 400 error.
   Impact: Employees with no assigned cases cannot list documents.

HIGH BUGS (Functional / Data Integrity)
======================================================================

#11 New Case Client Dropdown No Firm Scoping
    File: src/app/(dashboard)/cases/new/page.tsx:84
    Bug: Fetches ALL clients with no firm_id filter.
    Impact: Firm A can attach Firm B's clients to cases.

#12 Case Detail No Role-Based Access Control
    File: src/app/(dashboard)/cases/[id]/page.tsx:220-244
    Bug: Delete, Edit, Status buttons visible to ALL users.
    Impact: Junior associates can delete cases or mark them won.

#13 Client Delete Cascade N+1 Queries
    File: src/app/(dashboard)/clients/[id]/page.tsx:109-115
    Bug: 4 queries per case × N cases. 20 cases = 80+ sequential
         DB queries. Individual errors silently ignored.
    Impact: Slow deletion. Partial failures leave orphaned data.

#14 Pagination Doesn't Reset on Filter Change
    Files: cases/page.tsx:99, clients/page.tsx:73
    Bug: User on page 5 types search with 2 results → sees 0.
         Page state never resets when search/filter changes.
    Impact: Users think search is broken when results exist.

#15 Conflicting Success/Error Toasts on Case Create
    File: src/app/(dashboard)/cases/new/page.tsx:267-274
    Bug: Partial upload failures show error toast AND success
         toast, then redirect. User confused about outcome.
    Impact: Users don't know if case was created or not.

#16 Invoice Creation Missing Firm Scoping
    File: src/app/api/invoices/route.ts:40-44
    Bug: Client lookup has no firm_id filter. Users can create
         invoices for clients from other firms.
    Impact: Cross-firm invoice creation possible.

#17 Duplicate Subscription Race Condition
    File: src/app/api/payments/verify/route.ts:73
    Bug: No check for existing active subscription before insert.
         Same Razorpay payment can be verified repeatedly.
    Impact: Duplicate subscription records from same payment.

#18 Collections POST No Invoice Firm Check
    File: src/app/api/collections/route.ts:63-86
    Bug: Creates collection log for any invoice_id without
         verifying invoice belongs to user's firm.
    Impact: Cross-firm collection log creation.

#19 Expenses PATCH/DELETE Fails for Users Without Firm
    File: src/app/api/expenses/route.ts:136,161
    Bug: .eq("firm_id", undefined) matches nothing when user
         has no firm_id. Employees can't manage own expenses.
    Impact: Expense management broken for solo employees.

#20 Time Entries No Case Ownership Check
    File: src/app/api/time-entries/route.ts:59
    Bug: POST inserts with any case_id without verifying the
         case belongs to the user's firm.
    Impact: Time entries can reference wrong firm's cases.

#21 AI Analyzes Deleted Cases
    File: src/app/api/ai/analyze/route.ts:48-53
    Bug: No .is("deleted_at", null) filter on case query.
    Impact: AI can analyze soft-deleted cases.

#22 AI Quota Consumed on Failure
    Files: api/ai/analyze/route.ts:82, api/ai/chat/route.ts:105
    Bug: logAiQuery called even when analysis/chat fails.
    Impact: Failed requests consume daily quota unfairly.

#23 AI Chat Returns 200 for Unconfigured AI
    File: src/app/api/ai/chat/route.ts:70-78
    Bug: Returns HTTP 200 with text message when AI_API_KEY
         missing instead of 503 Service Unavailable.
    Impact: Clients can't detect AI is unavailable.

#24 Invoices No Zod Schema Validation
    File: src/app/api/invoices/route.ts:82
    Bug: Raw body fields destructured and inserted directly.
    Impact: Malformed data passes to database.

#25 Expenses No Zod Schema Validation
    File: src/app/api/expenses/route.ts:63-64
    Bug: Same issue. No schema validation on POST or PATCH.
    Impact: Malformed data passes to database.

#26 Invoices Race Condition on Fallback Number
    File: src/app/api/invoices/route.ts:72
    Bug: Date.now().toString().slice(-4) can collide under
         concurrent requests producing duplicate invoice numbers.
    Impact: Duplicate invoice numbers possible.

#27 Subscriptions plan_id Always Null
    File: src/app/api/subscriptions/route.ts:183
    Bug: plan_id is hardcoded to null. Plan slug only in JSON
         notes field, making it unqueryable.
    Impact: Plan-gating features break. Can't query by plan.

#28 Documents Storage Bypass When file_size=0
    File: src/app/api/documents/route.ts:79-80
    Bug: fileSize=0 or null skips storage limit check.
    Impact: Users can upload unlimited zero-size documents.

#29 Settings Save Partial Failure
    File: src/app/(super-admin)/super-admin/settings/page.tsx
    Bug: For-loop saves. If 3rd of 10 fails, first 2 committed.
    Impact: Inconsistent platform configuration.

#30 Subscription Override Creates Without plan_id
    File: src/app/api/admin/subscription-override/route.ts:46-50
    Bug: New subscription created without plan_id.
    Impact: Active subscription with no plan breaks features.

======================================================================
CROSS-CUTTING / ARCHITECTURAL ISSUES
======================================================================

A. Zero API Routes for Super Admin (All Client-Side)
   All super admin operations depend entirely on RLS.
   No server-side auth, audit logging, or input validation.

B. N+1 Query Patterns
   - Users page: 500 queries for 100 users
   - Analytics: Fixed (batch queries)
   - Client delete cascade: 80+ sequential queries

C. No Pagination on Super Admin Pages
   Users, cases, clients, documents all load entire tables.

D. Inconsistent firm_id Handling
   - Some pages: firm_id from profile
   - Some pages: firm_id falls back to user.id
   - Some pages: no firm_id at all
   - New inserts: many missing firm_id

E. In-Memory Rate Limiter Ineffective
   Serverless functions get fresh Maps on each invocation.

F. DB Migrations Still Needed
   - next_invoice_number RPC function
   - coupon_uses(coupon_id,user_id) unique constraint
   - firm_id columns on collection_logs and time_entries
