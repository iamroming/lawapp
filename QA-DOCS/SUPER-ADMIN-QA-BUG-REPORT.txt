CRITICAL BUGS (Security / Data Integrity / Platform-Breaking)
======================================================================

#1 Razorpay Annual Billing Charges 12x Instead of 1x
  File: src/app/api/subscriptions/route.ts:136
  Bug: `total_count: billingCycle === "annual" ? 12 : 6`
       For annual plans, Razorpay will charge 12 times. A ₹2,999/year
       plan becomes ₹35,988/year. For monthly, 6 months is acceptable.
  Impact: MASSIVE overcharging. Every annual subscriber gets charged
          12x the intended amount. Immediate financial damage.

#2 Coupon Plan Dropdown Sends Slugs Instead of UUIDs
  File: src/app/(super-admin)/super-admin/coupons/page.tsx:292-298
  Bug: Plan dropdown values are "solo", "professional", etc. But
       coupon_codes.plan_id is a UUID column. Sending "solo" into
       a UUID field will either error or create orphan references.
  Impact: Coupon plan restriction is completely broken. All coupons
          created with a plan restriction will fail.

#3 User Detail Page Has WRONG Role Values
  File: src/app/(super-admin)/super-admin/users/[id]/page.tsx:117
  Bug: Role Select offers "admin", "lawyer", "paralegal", "staff".
       Valid roles are: owner, partner, senior_associate, associate,
       junior_associate, paralegal, intern, office_admin, super_admin.
       Only "paralegal" overlaps. Setting invalid roles breaks RBAC.
  Impact: Any role change from this page breaks the user's access
          control. The app may crash or grant unexpected permissions.

#4 No API Routes for Super Admin Operations
  File: src/app/(super-admin)/super-admin/* (all pages)
  Bug: The ENTIRE super admin section uses client-side Supabase
       queries. There are zero API routes (src/app/api/super-admin/
       does not exist). All mutations depend entirely on RLS.
  Impact: If RLS is misconfigured, any authenticated user could
          perform super admin operations from the browser console.

#5 Document Deletion Bypasses All Security
  File: src/app/(super-admin)/super-admin/documents/page.tsx:33-38
  Bug: `supabase.from("documents").delete().eq("id", id)` — hard
       DELETE with no firm scoping, no audit logging, no confirmation
       beyond browser confirm(), no soft-delete pattern.
  Impact: Super admin can permanently delete any firm's documents
          with no audit trail. Data loss is irreversible.

#6 Platform Settings Mutated Directly From Client
  File: src/app/(super-admin)/super-admin/settings/page.tsx:35-42
  Bug: Platform settings (maintenance_mode, allow_signups, etc.)
       are updated via direct Supabase client writes. No server-side
       authorization, no audit logging, no rate limiting.
  Impact: Any authenticated user could enable maintenance mode and
          lock out ALL users if RLS allows it.

#7 Audit API Only Returns Current User's Logs
  File: src/app/api/audit/route.ts:16
  Bug: `.eq("user_id", user.id)` — hardcoded to current user.
       Super admin sees only their own activity, not platform-wide.
  Impact: Audit trail is useless for super admins. Cannot investigate
          security incidents or user actions.

#8 Activity Page Queries Wrong Table Name
  File: src/app/(super-admin)/super-admin/activity/page.tsx:22
  Bug: Queries `activity_logs` but audit system uses `audit_logs`.
       If these are different tables, super admin sees wrong data.
  Impact: Activity logs may show nothing or wrong data.

#9 Reports byType Uses Wrong Field Name
  File: src/app/api/reports/route.ts:50
  Bug: `c.type || "Other"` — but Case type is `case_type`, not `type`.
       Since `c.type` is always undefined, ALL cases show as "Other".
  Impact: Case type breakdown report is completely non-functional.

#10 Analytics N+1 Queries Will Timeout
  File: src/app/api/analytics/route.ts:94-116, 195-206, 292-310
  Bug: client_ltv, profit_by_case_type, client_retention all make
       individual queries per client/case. 200 clients = 401 queries.
  Impact: Analytics API will timeout on any production workload.

#11 Revenue Page Shows Cross-Firm Client Payments
  File: src/app/(super-admin)/super-admin/revenue/page.tsx:18-21
  Bug: Queries payments and invoices tables with NO firm_id filter.
       ALL firms' client payments are visible and intermixed.
  Impact: Massive cross-firm data leak. Revenue of all firms visible
          without any filtering capability.

#12 Subscription Webhook Never Sets plan_id
  File: src/app/api/subscriptions/webhook/route.ts:54-61
  Bug: subscription.activated updates status and expires_at but
       never sets plan_id. Subscriptions created with plan_id: null
       stay null forever.
  Impact: All plan-gating features break. Users can't access features
          their plan should include.

#13 Subscription DB Failure Silently Ignored
  File: src/app/api/subscriptions/route.ts:169-171
  Bug: If DB insert fails after Razorpay subscription is created,
       the error is only logged. User sees success but subscription
       record doesn't exist locally.
  Impact: Orphaned Razorpay subscriptions with no local record.
          Webhook will fail to find matching subscription.

#14 eCourts GET Returns All Cases When No firm_id
  File: src/app/api/ecourts/route.ts:129-137
  Bug: If user has no firm_id, the query runs without any firm
       filtering, returning ALL active ecourts cases across firms.
  Impact: Cross-firm court case data leak.

#15 Revenue Calculation Includes All-Time Payments
  File: src/app/(super-admin)/super-admin/subscriptions/page.tsx:142
  Bug: `subscriptions.reduce((sum, s) => sum + (s.amount_paid || 0))`
       Sums all historical payments including cancelled/expired.
       Labeled as "Revenue" which is misleading.
  Impact: Revenue numbers are inflated and inaccurate.

SYSTEMIC ISSUES (Architecture)
======================================================================

A. Zero API Routes for Super Admin
   All operations are client-side Supabase. No server-side:
   - Authorization verification
   - Audit logging
   - Input validation
   - Rate limiting
   - CSRF protection (beyond middleware)

B. N+1 Query Patterns Everywhere
   - Users page: 501 queries for 100 users
   - Analytics: 401 queries for 200 clients
   - eCourts sync: double-fetching from external API

C. No Pagination on Any Super Admin Page
   - Users, cases, clients, documents all load entire tables
   - Will crash browser on large datasets

D. Inconsistent Mutation Patterns
   - Some use API routes (coupon create, subscription override)
   - Others use direct Supabase client (user toggle, document delete)
   - No consistent security model

E. Missing Error Handling
   - All fetches silently swallow errors
   - All mutations show success unconditionally
   - Loading states stuck on failure
