PART 2: HOW THE APP WORKS
================================================================================

ARCHITECTURE:
- Frontend: Next.js 16.2.10 (Turbopack) + React + TypeScript
- Backend: Supabase (PostgreSQL + Auth + RLS)
- Styling: Tailwind CSS v4 (light theme only)
- Payments: Razorpay
- Storage: Cloudinary (client-side unsigned uploads)
- AI: OpenAI-compatible API (mimo-v2.5-free model)

DATABASE SCHEMA:
- profiles: User accounts (id, firm_id, role, full_name, email)
- firms: Law firms (owner = profile.id)
- cases: Legal cases (firm_id, client_id, assigned_to, status)
- clients: Client records (firm_id, created_by)
- documents: File attachments (firm_id, uploaded_by, cloudinary references)
- invoices: Billing (firm_id, issued_by, invoice_number, amount)
- payments: Payment records (firm_id, received_by)
- expenses: Firm expenses (firm_id, user_id, category, amount)
- time_entries: Billable hours (firm_id, lawyer_id, case_id)
- timesheets: Time tracking (firm_id, user_id, hours)
- active_timers: Running timers (user_id, case_id)
- hearings: Court dates (firm_id, case_id)
- messages: Internal messaging (firm_id, sender_id)
- notifications: User notifications (firm_id, user_id)
- tasks: Task management (firm_id, assigned_to)
- tags: Client/case tags (firm_id)
- consultations: Client consultations (firm_id)
- coupon_codes: Discount coupons (created_by super_admin)
- coupon_uses: Coupon redemption tracking
- user_subscriptions: Active subscriptions (plan, status, firm_id)
- subscription_plans: Available plans (Solo/Professional/Firm/Enterprise)
- collection_logs: Payment collection tracking (firm_id, invoice_id)
- ecourts_cases: Court case tracking (linked to cases)
- quotation_items: Quotation line items
- quotations: Client quotations (firm_id, client_id)

ROW LEVEL SECURITY (RLS):
All tables have RLS enabled. Policies follow this pattern:
- Owners/Partners: See ALL firm data (firm_id = user's firm_id)
- Employees: See only data they created or are assigned to
- Super Admins: Use service-role client (bypasses RLS entirely)

AUTHENTICATION:
- Supabase Auth (email/password)
- Roles: owner, partner, senior_associate, associate, employee, intern, paralegal
- Super Admins: Separate table (super_admins), bypass all RLS
- Session management via Supabase JWT tokens

USER ROLES & PERMISSIONS:
- owner: Full firm access, billing, team management
- partner: Full firm access, billing
- senior_associate: Can create cases, clients, invoices, time entries
- associate: Can create cases, clients, time entries
- employee: Read-only (can view firm data)
- intern: Read-only
- paralegal: Read-only

FIRM ISOLATION:
Every table has a firm_id column. RLS policies ensure:
1. Users can only see data from their own firm
2. Owners/partners see all firm data
3. Employees see only data they created or are assigned to
4. Super admins bypass all RLS via service-role client

DATA FLOW:
1. User signs up → profile created with firm_id
2. Creates cases/clients → firm_id automatically set from profile
3. Uploads documents → stored in Cloudinary, metadata in Supabase
4. Creates invoices → invoice number generated atomically via RPC
5. Processes payments → Razorpay handles payment, webhook updates subscription
6. AI tools → messages sent to AI API with prompt injection protection

KEY API ROUTES:
- /api/auth/signup - User registration
- /api/clients - Client CRUD
- /api/cases - Case CRUD
- /api/documents - Document upload/delete
- /api/invoices - Invoice CRUD with auto-numbering
- /api/expenses - Expense tracking
- /api/time-entries - Billable time tracking
- /api/payments/* - Razorpay payment processing
- /api/quotations - Quotation generation
- /api/ai/* - AI chat, drafting, research, analysis
- /api/admin/* - Super admin operations (coupons, subscriptions)
- /api/courts/* - Indian court integration (eCourts, High Courts)
