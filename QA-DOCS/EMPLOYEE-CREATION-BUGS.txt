BUG #1 (CRITICAL) — Team members list shows ALL users, not just firm
======================================================================
File: src/app/(dashboard)/settings/page.tsx:235-239

Current code:
  const { data: teamData } = await supabase
    .from("profiles")
    .select("id, full_name, email, role")
    .neq("id", user.id)
    .order("full_name");

Problem: No firm_id filter. Owner sees ALL users in the database,
not just their firm members. This is a data leak.

Fix: Add .eq("firm_id", firmId) filter.

BUG #5 (MEDIUM) — Role hierarchy check blocks same-level role changes
----------------------------------------------------------------------
File: src/app/api/team/invite/route.ts:101

Current code:
  if (theirLevel <= myLevel && profile?.role !== "super_admin") {
    return NextResponse.json({ error: "Cannot change role..." });
  }

Problem: `<=` means a Partner cannot change another Partner's role
at all — even to demote them. Should be `<` (strictly lower level)
to allow same-level role changes.

Fix: Change `theirLevel <= myLevel` to `theirLevel < myLevel`.

----------------------------------------------------------------------
BUG #6 (MEDIUM) — Remove member has no role hierarchy check
----------------------------------------------------------------------
File: src/app/api/team/[id]/route.ts

Problem: Any owner or partner can remove any other owner/partner.
A partner could remove the owner. No hierarchy protection.

Fix: Add role hierarchy check — partner cannot remove owner,
senior_associate cannot remove partner, etc.

----------------------------------------------------------------------
BUG #7 (MEDIUM) — Redeem code overwrites existing firm membership
----------------------------------------------------------------------
File: src/app/api/team/redeem-code/route.ts:64-79

Problem: If a user already belongs to a firm (firm_id is set),
redeeming a new code silently overwrites their firm_id. User
could be moved from Firm A to Firm B without warning.

Fix: Check if user already has a firm_id. If so, return error:
"You already belong to a firm. Leave your current firm first."

----------------------------------------------------------------------
BUG #8 (MEDIUM) — Subscription lookup fails for employees
----------------------------------------------------------------------
File: src/app/(dashboard)/settings/page.tsx:253-260

Current code:
  .eq("user_id", user.id)  // <-- employee's ID

Problem: Subscription is stored under the owner's ID (via firm_id).
When an employee loads settings, subscription query returns nothing.
Plan shows as null, usage bars don't show, upgrade prompts broken.

Fix: Look up firm_id first, then query subscription with owner's ID:
  const firmOwner = profile.firm_id || user.id;
  .eq("user_id", firmOwner)
