CRITICAL BUGS (Security / Data Integrity)
======================================================================

#1 Open Redirect in Auth Callback
  File: src/app/auth/callback/route.ts:7
  Bug: `next` parameter from URL is used directly in redirect without
       validation. Attacker can craft ?next=https://evil.com to steal
       session tokens after authentication.
  Impact: Session hijacking via phishing link.

#2 Client Portal createUser Uses Anon Key Instead of Service Role
  File: src/app/api/client-portal/route.ts:36
  Bug: `supabase.auth.admin.createUser()` requires service role key,
       but the route uses the session client (anon key). This call
       will always fail with permission error.
  Impact: Client portal user creation is completely broken.

#3 Privilege Escalation via signup_mode
  File: src/app/api/auth/signup/route.ts:67
  Bug: `signup_mode` is extracted from request body and stored in
       `user_metadata` without validation. If signup_mode === "owner",
       it creates an owner profile. No server-side check for valid
       invite code when signup_mode is "employee".
  Impact: Any user can create an owner account with full firm access.

#4 Client Detail Page Bypasses Firm Scoping
  File: src/app/(dashboard)/clients/[id]/page.tsx:51
  Bug: `supabase.from("clients").select("*").eq("id", params.id)`
       has no firm_id filter. Any authenticated user can view any
       client by guessing the UUID.
  Impact: Cross-firm client data leak.

#5 Client Delete Bypasses Firm Scoping
  File: src/app/(dashboard)/clients/[id]/page.tsx:66-84
  Bug: Delete handler performs all cascading deletes directly via
       client-side Supabase without firm_id checks. Any user can
       soft-delete any client and all related records.
  Impact: Cross-firm data destruction.

#6 Document Delete Bypasses Firm Scoping
  File: src/app/(dashboard)/documents/page.tsx:188-209
  Bug: `handleDelete` does `supabase.from("documents").update(
       {deleted_at}).eq("id", doc.id)` with no firm_id check.
  Impact: Any user can soft-delete any document.

#7 AI Analyze API Has No Case Ownership Validation
  File: src/app/api/ai/analyze/route.ts:40-44
  Bug: Case query `.eq("id", caseId).single()` has no firm_id filter.
       Any user can analyze any case by providing its ID.
  Impact: Cross-firm case data leak via AI analysis.

#8 Calendar Clients Query Not Firm-Scoped
  File: src/app/(dashboard)/calendar/page.tsx:228-232
  Bug: `supabase.from("clients").select("id, full_name")` fetches
       ALL clients across ALL firms. Users can see other firms'
       clients in the hearing scheduling dropdown.
  Impact: Cross-firm client data leak in calendar.

#9 Calendar Hearings Insert Missing firm_id and created_by
  File: src/app/(dashboard)/calendar/page.tsx:245-254
  Bug: Direct Supabase insert without firm_id or created_by fields.
       Newly created hearings are invisible to firm-scoped queries.
  Impact: Data integrity — hearings created but not visible.

#10 Revenue Reports Missing firm_id Filter
  File: src/app/(dashboard)/reports/revenue/page.tsx:102-115
  Bug: Payments and invoices queries for owner/partner have NO firm_id
       filter. Owners see payments from ALL firms.
  Impact: Cross-firm financial data leak.

#11 Super Admin Coupon Operations Bypass API
  File: src/app/(super-admin)/super-admin/coupons/page.tsx:107-125
  Bug: toggleActive, deleteCoupon, viewUses all use direct Supabase
       client instead of API routes. No server-side authorization.
  Impact: Any authenticated user could toggle/delete coupons if RLS
          is not properly configured.

#12 In-Memory Rate Limiter Ineffective in Serverless
  File: src/app/api/auth/signup/route.ts:6
  Bug: signupAttempts Map is in-memory. In Vercel/serverless, each
       invocation gets a fresh copy. Rate limit is bypassed.
  Impact: Unlimited signup attempts in production.

SYSTEMIC ISSUES (Architecture)
======================================================================

A. Client-Side Supabase Usage Bypasses API Routes
   Multiple pages query Supabase directly from the browser:
   - cases/[id]/page.tsx (fetch, delete, update)
   - clients/[id]/page.tsx (fetch, delete)
   - documents/page.tsx (delete)
   - calendar/page.tsx (insert hearings)
   - settings/page.tsx (notification save)
   - tasks/page.tsx (move, delete)
   - expenses/page.tsx (delete)
   - super-admin/users/page.tsx (toggle, role change)
   - super-admin/coupons/page.tsx (toggle, delete)

   This bypasses: authorization, firm scoping, validation,
   audit logging, rate limiting, and CSRF protection.

B. Inconsistent Role Definitions
   - Client-side: super_admin treated as owner
   - Server-side: super_admin NOT in owner checks
   - Impact: Data visibility mismatch between UI and API

C. Inconsistent firmId Fallback
   - Some files: profile?.firm_id || user.id
   - Others: profile?.firm_id (no fallback)
   - Impact: Different data when firm_id is null

D. Inconsistent Soft-Delete vs Hard-Delete
   - Most modules: soft-delete with deleted_at
   - time_entries: hard DELETE
   - expenses: hard DELETE
   - Impact: Data recovery impossible for some records

E. Missing Error Boundaries
   - Most async operations catch errors with console.error only
   - No error state set in UI
   - Users see stale/empty data with no indication of failure

F. Infinite Re-render Risk
   - createClient() in useEffect dependency arrays
   - If not singleton, causes infinite loops
