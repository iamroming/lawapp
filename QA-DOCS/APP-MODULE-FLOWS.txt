======================================================================
        CASEFILES — ENTIRE APPLICATION MODULE FLOW DOCUMENTATION
======================================================================
A law practice management SaaS for Indian lawyers and law firms.
Stack: Next.js 16, Supabase (PostgreSQL + Auth), Razorpay, Cloudinary


======================================================================
1. AUTHENTICATION & SIGNUP
======================================================================

User clicks "Sign Up"
        ↓
Signup page collects: name, email, password, firm name
        ↓
POST /api/auth/signup
        ↓
Supabase Auth creates user in auth.users
        ↓
Database trigger fires → creates row in profiles table
        ↓
Confirmation email sent to user
        ↓
User clicks link → email confirmed
        ↓
Login page → enters email + password
        ↓
Supabase Auth validates credentials → creates session
        ↓
Middleware reads session → sets cookies
        ↓
Redirect to /dashboard (or /subscription-required if no plan)


======================================================================
2. SUBSCRIPTION & PAYMENTS (RAZORPAY)
======================================================================

User clicks "Upgrade" on a plan
        ↓
Frontend calls POST /api/payments/create-order
  { planSlug: "professional", billingCycle: "monthly", couponCode: "SAVE30" }
        ↓
API calculates final amount (applies coupon discount if any)
        ↓
Razorpay order created via Razorpay SDK
        ↓
Razorpay checkout.js loaded → payment popup opens
        ↓
User pays via UPI / Card / Netbanking
        ↓
Razorpay handler fires → calls POST /api/payments/verify
  { razorpay_order_id, razorpay_payment_id, razorpay_signature, planSlug }
        ↓
API verifies signature with Razorpay secret
        ↓
If coupon was used:
  → coupon_codes.current_uses incremented
  → coupon_uses record created (who used what, when)
        ↓
user_subscriptions row created/updated:
  → plan_id, status: "active", starts_at, expires_at
  → amount_paid, payment_method: "razorpay"
  → notes: { plan_slug, billing_cycle }
        ↓
Subscription limits now active:
  → cases, users, storage, AI queries
        ↓
Middleware checks subscription on every request
  → /subscription-required if expired/missing
  → Inherits via firm_id (employees see owner's subscription)


======================================================================
3. COUPON SYSTEM
======================================================================

Super Admin creates coupon at /super-admin/coupons
        ↓
POST /api/admin/coupons
  { code: "SAVE30", discount_type: "percent", discount_value: 30,
    max_uses: 100, max_per_user: 1, billing_cycle: "both" }
        ↓
coupon_codes row created
        ↓
User enters coupon on /subscription page
        ↓
POST /api/coupons/validate
  → checks: is_active, valid_from/until, max_uses, max_per_user
  → checks: billing_cycle match, plan match
        ↓
API returns: { valid: true, discount_type, discount_value }
        ↓
Frontend updates plan prices (strikethrough + discounted)
        ↓
User clicks Upgrade → Razorpay for discounted amount
        ↓
POST /api/coupons/apply
  → atomic increment of current_uses
  → coupon_uses record created
  → subscription activated
        ↓
If free coupon → skips Razorpay, activates directly

9. DOCUMENTS MANAGEMENT
======================================================================

User clicks "Documents" in sidebar
        ↓
GET /api/documents
  → owner/partner: all firm documents
  → employees: own uploads + assigned case docs
        ↓
Document list with categories:
  → petition, affidavit, evidence, judgment, agreement,
    correspondence, other
  → confidential flag
        ↓
User uploads document:
        ↓
Pre-flight check → GET /api/documents/storage-check
  → sums file_size of all firm documents
  → compares against plan limit (e.g., 3 GB for Professional)
  → if exceeded → "Storage limit reached" error
        ↓
File uploaded to Cloudinary (client-side)
  → uploadToCloudinary(file, "CaseFiles/documents")
  → returns secure_url
        ↓
POST /api/documents
  → verifies case belongs to firm (if linked)
  → inserts with: title, file_url, file_name, file_type, file_size
  → sets firm_id, uploaded_by
  → if insert fails → deletes orphaned Cloudinary file
        ↓
Delete flow:
  → verifies document belongs to firm
  → deletes from Cloudinary
  → soft-deletes from database (deleted_at)

25. MULTI-TENANCY & DATA ISOLATION
======================================================================

Every table has firm_id column
        ↓
Middleware on every API request:
  → reads user session
  → looks up firm_id from profiles
  → sets supabase.auth.setClaims({ firm_id })
        ↓
Row-Level Security (RLS) policies:
  → users can only see rows where firm_id matches
  → owner/partner see all firm data
  → employees see only their own + assigned data
        ↓
API-level checks:
  → most routes verify firm_id before CRUD
  → prevents cross-firm data access
